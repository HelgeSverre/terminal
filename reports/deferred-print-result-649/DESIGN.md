# Deferred print result materialization

Frozen baseline 649083cde98fc2f4c8cd2e65104d4f1ebcb601f8. Scratch only. This experiment is distinct from the rejected bulk UTF-8 prototypes.

Source audit: PrintEffect has exactly four non-nil producers. Fresh scalar, Unicode same-row span and ASCII span all construct String for their last scalar; cluster extension already owns the combined String. Every producer also supplies complete repeat attributes. The consumer's fallback to current pen/link/protection is therefore unreachable for production-produced effects. Ignored/default-ignorable, capped, failed admission and orphan-attachment paths intentionally leave the previous result unchanged.

Replace the two parallel optional fields with one optional PrintedGrapheme whose Content is scalar(Unicode.Scalar) or cluster(String), with nonoptional PrintAttributes. Preserve each producer's existing assignment location and attribute source. The consumer materializes text once per applied document batch, then installs the coherent text/attributes into REP state. No compatibility aliases, no representation changes to rows or emulator's persistent REP state, no changed mutation/history/revision logic. Extension results continue using previous-cell attributes, even if parser SGR/link/protection changed.

Load-bearing evidence: fresh Unicode source still performs String(scalar) immediately after replacePrintedScalar, and both span paths construct String(last); these values can be overwritten by later scalars/spans before apply consumes the result. The fresh 9354 sample supports Document.print as a dominant owner, but does not separately resolve the inlined String(scalar) conversion, so it cannot establish the removable percentage. Its 553-sample cluster-print frame and 35 SmallString-append samples describe cluster work that this change does not remove. Actual gains must be measured; do not attribute those samples to this optimization.

Risks: larger/differently laid out result enum, ARC switching between scalar/cluster cases, and code-generation changes can offset fewer String constructions. No assumed gain or further annotation variants.

Validation prepared: full ownership and emulator suites baseline/candidate; 63 direct-document scenario combinations across widths 1/2/9, batch sizes1/3/1024, fresh/combining/VS/ZWJ/prepend/ignored/control/70-mark cap cases. Exact serialized result text scalar values, attributes, mutation/consumption/history counts, row IDs/revisions/cells/cost, cursor/wrap comparison across executables; retained row/screen assertions. 54 emulator REP traces across widths1/2/16, six graphemes including capped cluster, changed SGR/link/protection before combining extension, ignored scalar, REP and DSR; full stable snapshot and reply byte comparison. Existing suites add alternate/margins/insert/wrap/history/ownership coverage. No compiler or timing until slot released.
