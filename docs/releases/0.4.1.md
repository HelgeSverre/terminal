This release makes the pane color popover, Settings and the Edit menu work
from the keyboard, and draws output with less processor time.

- Right-clicking a pane header opens the color popover where you clicked.
  Shell > Pane Color… opens it from the keyboard, also when the header is
  hidden. Arrow keys, Home and End move through the colors and preview them,
  Return or Space keeps one, and Escape puts back the color the pane had.
  Tab and Shift-Tab move between the colors and the hex field.
- VoiceOver reads the colors as a group of radio buttons, and the pane
  header offers Choose Pane Color and Close Pane as actions.
- AppleScript can read and change a pane's color with `read pane color` and
  `apply pane color`, which takes a hex value, a palette name or `default`.
  `configure preferences` takes a `default pane color`.
- Tab and Shift-Tab move through every field, checkbox and button in
  Settings, whatever the system's Keyboard Navigation setting. Space toggles
  a checkbox, Left and Right change the pane dimming level, and Up and Down
  change the section. VoiceOver reads each field's hint.
- The Edit menu has Undo, Redo, Cut and Delete for the find bar, Settings and
  the hex field. In the terminal, ⌘Z, ⇧⌘Z and ⌘X still go to the running
  program, and Copy is available only when text is selected.
- The PTY is read in 64 KiB slabs instead of 16, which raises foreground
  throughput by 12% on short ASCII lines, 11% on long ones, 4% on truecolor
  and 5% on mixed Unicode. A key typed during a flood can wait behind up to
  128 KiB of output instead of 64 KiB; its slowest arrival rose from 0.40 to
  0.67 ms.
- Each frame is drawn from one reused buffer, so drawing uses 7% to 28%
  less processor time per MiB of output. These are measurements on one Mac;
  see the
  [method and results](https://github.com/HelgeSverre/terminal/blob/main/reports/reader-batches-2026-11-12/README.md).

Installed copies of 0.4.0 offer this update at launch or from Check for
Updates… in the app menu.
